Slide 3
Title: Objetivo do projeto
- Implementar um interpretador JVM educacional em C.
- Ler `.class`, decodificar estruturas e interpretar bytecodes.
- Priorizar clareza pedagógica e capacidade de evoluir (native hooks, testes).

Note: Slide curta — introdução para alinhar expectativas.

Slide 4
Title: Arquitetura Geral (mapa rápido)
- `main.c` / `java_frontend.c`: CLI e orquestração
- `leitor.c`, `formatoClassFile.h`: leitura e estruturas do `.class`
- `constantPoolDecoding.c`: helpers para decodificar constant pool
- `attributeDecoding.c`, `attributeStructs.h`: atributos e `Code`

- `executorInstrucoes.c`, `frames.h`: VM, loop de execução, instruções
- `instrucoes.c`: catálogo / metadados das instruções

Note: Aponte para `docs/architecture.drawio` para o diagrama completo.

Slide 5
Title: Parsing de `.class` — fluxo
1. `main` chama leitor para abrir o arquivo `.class`.
2. `leitor.c` lê cabeçalho, constant pool, fields, methods, attributes.
3. Estruturas em memória: `ClassFile`, `cp_info`, `method_info`, `attribute_info`.
4. `attributeDecoding.c` extrai `Code` attributes com bytecodes.

Note: Explique responsabilidade de cada struct (quem aloca, quem libera).

Slide 6
Title: Constant Pool e Resolução
- `constantPool.h` + `constantPoolDecoding.c` decodificam entradas (UTF8, String, Integer, Methodref, etc.)
- Resolução: `decodeInstructionOp` & helpers que transformam índices em texto (e.g., `java/lang/Object-><init>`)
- Uso: `getMethodCode`, `exec_getfield`, `exec_invoke*` usam essas resoluções para logs/simulações.

Note: destaque diferenças entre resolução estática (index → entry) e linking (runtime simplificado).

Slide 7
Title: Executor (VM) e Frames
- `executorInstrucoes.c` contém:
  - Loop principal: `executar(Frame *frame)` (fetch → dispatch)
  - Tabela `instrucoes_exec[256]` de ponteiros para handlers
  - Helpers: `push_stack`, `pop_stack`, `push_long`, `pop_long`, `push_double`, `pop_double`
- `frames.h`: definição de `Frame` (operand_stack, local_variables, pc, max_stack, code_length)

Note: comente decisões práticas (representação de long/double em dois slots, uso de int para referências simuladas).

Slide 8
Title: Fluxo de Execução (exemplo simplificado)
1. `inicializarAmbiente(classFile)` configura `GLOBAL_CP`.
2. `getMethodCode(classFile, "main", "()V")` retorna `Code` attribute.
3. Cria `Frame` para `main` e chama `executar(frame)`.
4. `executar` faz fetch do opcode, lookup em `instrucoes_exec`, chama handler.
5. Handlers manipulam PC, pilha, locais; alguns tratam argumentos (ldc/ldc_w/ldc2_w, getstatic).

Note: explicar que `func(frame)` deve ajustar `frame->pc` conforme argumentos.

Slide 9
Title: Implementação do `tableswitch` (detalhe)
- Opcode: `0xAA` (`tableswitch`) — possui padding para alinhar a 4-byte boundary.
- Formato (após padding): `defaultbyte`, `low`, `high`, então N offsets (4 bytes cada).
- Nossa implementação principal faz:
  - Calcula padding relativo à posição do opcode (`opcode_pos = pc-1`).
  - Lê `default`, `low`, `high` (big-endian signed 32-bit).
  - Calcula `index = pop_stack()`; se dentro de `[low,high]` pega offset correspondente.
  - PC final = `opcode_pos + branch_offset`.

Note: ressalte cuidados com leitura big-endian e checagens defensivas.

Slide 10
Title: Testes e exemplos
- `exemplos/` contém classes usadas para testar instruções (e.g., `tableswitch.class`).
- Como rodar:
  - `make`
  - `./leitor.exe exemplos/tableswitch.class` → escolha opção `2` para executar
- Logs úteis: `decodeInstructionOp` e prints em handlers (`Aviso: ...`, `--- [PUTFIELD] ...`) ajudam debugging.

Note: mencionar uso anterior de sanitizers (ASan/LSan) durante desenvolvimento.

Slide 11
Title: Memory Management e Boas Práticas
- Alocações: `leitor.c` cria estruturas aninhadas — cada `malloc` deve ter `free` correspondente.
- Arquivo `MEMORY_ISSUES_REPORT.md` e implementações de `freeClassFile` cuidam de liberação recursiva.
- Evitar double-free / use-after-free; validar ponteiros antes de liberar.

Note: mostre exemplo de free recursivo (breve) e onde foi aplicado.
